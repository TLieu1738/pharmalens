# PharmaLens roadmap

Status key: **Done** = implemented and tested · **Next** = planned for the next phase · **Later** = planned.
Nothing below "Done" exists in the application yet.

## Phase 1 — Core improvements (Done, on branch `phase-1`)

| Feature | Status |
| --- | --- |
| Interactive research protocol: draft → review/edit → approve → run; re-run with edits; discard | Done |
| Durable background jobs: database-backed queue, leases, heartbeat, crash recovery with bounded retries, cancellation, optional separate worker process | Done |
| Expanded retrieval: protocol-set limits (5–100 per source), paging on PubMed / Europe PMC / ClinicalTrials.gov, multiple literature queries, date and preprint filters, matching-vs-retrieved counts | Done |
| Reproducibility and audit trail: run record, searches run, deduplication merges, grounding removals with reasons, model settings | Done |
| Professional reports: protocol, methodology and data-source sections generated by code; conclusions and conflicting-evidence sections; empty sections omitted; Markdown and PDF export | Done |

## Phase 2 — Pharmaceutical intelligence (Next)

| Feature | Notes |
| --- | --- |
| Knowledge graph | Entities and relationships only where a source states them (Open Targets associations, ChEMBL mechanisms, trial interventions/conditions/sponsors, PubMed/NCT links); provenance on every edge; progressive expansion rather than one large render. Library to evaluate: Cytoscape.js or a lightweight force layout. |
| Clinical trial comparison | Side-by-side selection of trials; add primary/secondary outcomes from ClinicalTrials.gov; distinguish registered information from posted results, and state when results are unavailable. Timeline, sponsor and status distributions. |
| Drug pipeline view | Compounds grouped by ChEMBL max phase, filterable by disease, target, mechanism; never infer approval or phase. |
| PubChem integration | CID, formula, molecular weight, structure identifiers (InChIKey, SMILES), cross-references via PUG REST. |
| OpenAlex integration | Authors, institutions, topics, citation counts; deduplicated with PubMed/Europe PMC by DOI. |

## Phase 3 — Commercial intelligence (Later)

Access conditions must be confirmed before any integration; unavailable data will show a labelled empty state,
never estimates.

| Source | To verify before building |
| --- | --- |
| NICE technology appraisals and guidance | NICE's syndication API requires an application and licence; check terms for automated retrieval and display. |
| NHS dm+d | Distributed through NHS TRUD with registration; check licence for redistribution. |
| NHSBSA eMIT | Published as downloadable files; check licence and update cadence. Prices are indicative, not NHS net acquisition costs. |
| Economic evidence (costs, QALYs, ICERs) | Only as reported in appraisals or published studies, with comparator, perspective, time horizon and source; never calculated by PharmaLens when inputs are missing. |

## Phase 4 — Product polish (Later)

- Executive dashboard charts over time (research activity, discoveries) from stored data only.
- Cross-study comparison of populations, interventions and outcomes, without treating unlike studies as comparable.
- Follow-up questions answered from the session's retrieved evidence (or new retrieval), with the same grounding check.
- Saved topics with checks for new publications and trials (scheduled alerts once a scheduler is available).
- Comparative drug view across target, mechanism, phase, trials and publications, showing missing data explicitly.
- AI-suggested follow-up research questions, labelled as suggestions.

## Known limitations to address

- Retrieval takes top-ranked records per query (now configurable up to 100 per source); not a systematic review.
- Contradiction detection relies on the synthesis model reading abstracts, not formal meta-analysis.
- The evidence library aggregates up to 50 recent sessions with one query each; a single SQL query would scale better.
- Supabase's built-in email is rate limited on the free plan; production needs custom SMTP.
- Free hosting sleeps after inactivity; production needs an always-on instance.
